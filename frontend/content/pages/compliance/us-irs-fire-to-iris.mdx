## How IRIS filing works

IRIS, the Information Returns Intake System, offers two ways to file:

- **Taxpayer Portal.** A web portal. Returns are typed in by hand or uploaded as **CSV files of up to 100 records** per upload. No special software is needed.
- **Application to Application (A2A).** For larger volumes. Software sends returns in **XML** using the IRIS schemas.

Both need an **IRIS Transmitter Control Code (TCC)**. A TCC from FIRE does not carry over.

## What a FoxPro system has to change

Many FoxPro systems that handle 1099s write a FIRE file: fixed-width text records in the layout from IRS Publication 1220, built with low-level file commands such as `FCREATE`, `FWRITE` or `STRTOFILE`. IRIS does not accept that layout. Depending on your volume, the export needs to produce:

- **CSV in the IRIS template layout**, for the Taxpayer Portal, if you file a modest number of forms, or
- **IRIS XML**, for A2A, usually through software or a filing service that holds the IRIS schemas.

Two more things to check:

1. **TIN and name data.** Taxpayer IDs, names and addresses often sit in old tables with blanks and inconsistent formats. Bad data is rejected whichever system you use.
2. **Who files.** If a service bureau or software vendor filed for you through FIRE, ask how and when they move to IRIS. Your export format may need to change for them too.

## Your options

| Option | What it means | When it fits |
|---|---|---|
| **CSV for the portal** | Change the FoxPro export to the IRIS CSV template and upload it. | A modest number of forms, filed by your own team. |
| **Bridge to XML or a filing service** | A small program reads the 1099 data from your FoxPro tables and produces IRIS XML, or the format your filing service needs. | Larger volumes, or when the FoxPro code should not be touched. |
| **Migration** | Information-return reporting is rebuilt as part of moving the application to .NET and SQL Server. | A migration is planned anyway. Do not let the January 2027 season wait for it. |
